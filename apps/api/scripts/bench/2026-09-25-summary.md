## 结论与最终策略

1. **批改（check_production）必须用主模型 + 思考**：main+low/medium/max = **100%**，flash 各档最高 89% 且更慢（25s+）；两个模型的 off 档都只有 67%（思考是刚需，与模型无关）。选 **main + medium**（100% · 14s，比 low 峰值更稳）。
2. **生成类任务 off 就是最优**：填空生成思考档反而超时劣化（flash/high 50%）；理解/表达/Read 生成 off 均 100%（flash）；思考只增加 10-20 倍延迟。
3. **简单判定用 flash**：check_cloze flash/off 100% · 2.3s；judge flash/low 100%（off 89%，多 5s 换 11 个点的首过率，导入低频值得）。
4. **延迟红线**：实时交互（批改）>20s 不可接受 → main/medium 14s 达标；flash 思考档 25s+ 出局。

**最终矩阵（taskConfig）**：check_production = main/medium；check_cloze = flash/off；judge = flash/low；四个生成任务 = flash/off。
