# Phase 8 — Today 沉浸式答题改版

状态：done（2026-09-28）

## 目标与范围

- 移动端 Today 一题一屏，题目和反馈滚动，操作/输入固定底部。
- 主动不会与答错共享按题型揭示的纠错反馈；主动不会直接按 fail 结算。
- 顶部按 pass/basic_pass/fail/未做呈现进度；「今日学习」按学习项去重并提供只读答题记录及坏题入口。
- 右上撤销图标只撤销最近一次作答；精确回滚，重新排一题，区别于标记坏题。

## 决策记录

- 2026-09-29：主屏 PWA 实机最终确认键盘交互可用。多轮修正的根因是起初把问题当作单一高度/inset 计算，桌面模拟验证了结束位置却不能复现 iOS 原生聚焦滚动和动画；后续逐帧补偿虽然修正静态位置，却与浏览器滚动异步竞争而抖动。保留原位 `focus({preventScroll:true})`、触摸完成前锁定命中区域、click 后只移动 dock 的方案；今后此类改动以完整触摸 E2E 加主屏 PWA 真机动画验收为门禁，详见 TECHNICAL_DESIGN §7.6。
- 2026-09-29：`scrollY` 后验逐帧补偿虽让静态位置对齐，但主屏 PWA 实机动画重新抖动；撤回该补偿，改为触摸 `pointerdown` 对原位输入执行 `focus({preventScroll:true})`，不 `preventDefault`、不提前移动输入。click 前锁住卡高保证命中真实输入，click 后再预定位 dock；这与早期失败方案的区别是整个触摸期间输入不搬家。属于同一键盘交互问题的架构修正，实际 iOS 防滚动效果待验证。
- 2026-09-29：诊断面板实机读数表明键盘后 `scrollY=html.scrollTop=107`，顶栏 `top=-107`、题卡 `top=-41/bottom=282`，预置卡高约 390px 与可视高度 389px 匹配；空白与顶栏消失均来自 document 原生滚动未补偿，而非卡片自身高度错误。活动 Today 页面壳和独立 fixed 顶栏仅在输入/键盘阶段用实际 `scrollY` 同量校正 `top`，普通滚动不校正；不使用可能迟到的 `visualViewport.offsetTop`、不反复 `scrollTo`。真机动画与键盘持续性仍需复验。
- 2026-09-29：主屏 PWA 新截图显示卡片顶部被系统视口平移裁掉，底部输入区却与键盘之间仍有大段空白；既有“点击后预置 48% 卡高 + visualViewport.height 收缩”的策略可能与 iOS 原生视口平移重复计入。此前多次仅调定位未解决，先通过 `?kbdebug=1` 的只读视口诊断获取真机 `innerHeight` / visualViewport / 滚动 / 顶栏与卡片坐标，再决定是否替换聚焦架构；不对正常会话显示诊断。
- 2026-09-29：主屏 PWA 真机反馈键盘弹起后立即消失。完整触摸诊断确认旧 `pointerdown` 预定位使真实输入从 y≈585 移至 y≈231，同一次触摸的 click 改命中 main；早前 E2E 只派发 pointerdown，漏测触摸完成。改为原生点击先完成焦点、click 命中真实输入后才定位 dock，不再 `preventDefault`/手动 focus；保持顶栏不随 offset 平移。
- 2026-09-29：用户补充主屏 PWA 录屏后，发现此前整页 `translateY(visualViewport.offsetTop)` 补偿会在 iOS 异步视口事件下使顶栏与卡片一起上移/回弹；停止以 offset 驱动整页。填空/表达触屏聚焦前先预定位 dock，再 `focus({preventScroll:true})`，仅 dock/卡底随可见高度调整；填空 Today 取消 autoFocus。此为同一沉浸式答题范围内的键盘交互修复，效果待 iPhone 主屏 PWA 实测。
- 2026-09-29：真机验收发现上一版键盘结束位置正确、但弹起动画中顶端闪动；原因是聚焦时整页才从普通布局切到 fixed，并在 100px 键盘阈值处突然改变卡高。修正为活动会话入场即固定页面壳，卡高按当前可视高度连续取较小值；顶部保持同一布局，键盘逐步覆盖导航空间后只推动底部 dock。
- 2026-09-29：手机键盘适配沿用本阶段 Today 沉浸式卡范围。键盘打开状态与键盘占用高度分开判断：iOS Safari 可能同时报告缩小后的 `innerHeight` 和非零 `visualViewport.offsetTop`，此时旧高度差为 0，不能据此认定键盘已关闭。键盘期固定页面顶端和题目位置，仅调整卡片可视高度、底部输入区；底部导航隐藏，收键盘后恢复。
- 2026-09-28：按用户实际使用反馈，取消顺序回看导航，以「今日学习」只读列表代替；进度条只表达结果分布。
- 2026-09-28：撤销入口用单图标，确认层展示精确题目；只撤销最近一次正式作答，重练用另一道题，避免答案揭示后立即重选。
- 2026-09-28：撤销补强题沿用原配额槽位；普通撤销需恢复被替换的未固定个人例句与被裁剪的表达历史。若新例句已被用户固定或修改，拒绝撤销以保护用户数据。

## 遗留问题

- **部署前旧作答的撤销快照缺口**：见决策记录 2026-09-28「部署前旧作答撤销能力缺口」条——本次部署前在生产已答的表达题作答撤销时无法恢复被顶替例句/被裁剪历史，属一次性窄窗口，部署后新答不受影响。
- **撤销替换题唯一绑定未加防**：同 item 极端连撤两次且库存近枯时，理论上两道撤销替换任务可能绑定同一道题（重复练习，无数据损坏）；若后续再动撤销逻辑，建议在事务内 recheck 加同 session 唯一绑定守卫。
- **坏题与普通撤销的被顶替例句恢复不对称**：坏题撤销删除新例句但不恢复被顶替的旧例句（既有行为，本阶段未回归）；普通撤销已恢复。后续一致性打磨项。
- **弹层可访问性（非阻塞）**：「今日学习」弹层缺 aria-modal/Esc/焦点管理，撤销确认层缺 Esc/焦点陷阱；键盘可达性目前以 375x480 几何用例代理（iOS dvh 不随软键盘收缩，无法在 CI 模拟）。
- **小项顺延**：read_reinforcement 记录缺「· 补强」后缀（origin 判断用 `==='reinforcement'`）；今日学习弹层在数据未到时点击会迟到自动弹出；globals.css 中 header/nav 高度与 pb-safe-tight 表达式存在第三份硬编码副本；测试侧 cloze 主动不会缺零判定调用断言、undo 相关测试助手在三个 describe 重复。
