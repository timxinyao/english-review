# Today 沉浸式题卡设计

## 意图与验收

手机 Today 要让用户一题一屏、拇指区完成操作，减少没有学习价值的点击。主动不会应立刻揭示这道题的正确解法；答错沿用相同的纠错布局。结果进度和今日学习记录要易读，但不提供复杂的题目导航。

## 交互

- 顶部显示完成数/总数和 pass/basic_pass/fail/未做四色分布；点击打开按 Learning Item 去重的「今日学习」列表。展开后只读查看每次答题、正确答案与解释，并可标记坏题。
- 中间单题卡填满可用高度，题干和反馈滚动。底部操作区固定；填空、表达输入框亦在底部。选择题、填空题、表达题分别可直接声明不会。
- 主动不会和答错均停在当前卡看答案，再手动下一题。选择题勾正确项并显示理由；填空显示完整句及可接受答案；表达展示参考句和用法说明，用户实际作答失败则保留最小纠错 diff。
- 顶部右侧用一个撤销图标，确认层说明具体词和题型；仅撤销当天最近一次正式作答。最后一题完成后同样有入口。撤销后仍留在当前位置，原题作废但不标坏题，后部安排不同题目的替代任务。

## 服务端边界

- `answer` 的 `giveUp` 与其他答案字段互斥。结算为 fail；表达题不调用批改模型。正确答案仅在结算后返回。
- `undo` 在同一事务中恢复 attempt 的 pre-state、回减 daily_stats、新学额度和表达计数、取消本次补强及未固定个人例句、void attempt、取消旧任务并插入替代任务。若本次写入替换了旧个人例句或裁剪了表达历史，也恢复被替换/裁剪的数据；若新例句已被用户固定或修改，则拒绝普通撤销以保护用户数据。服务端按真实 attempt 插入顺序只允许最新作答；跨设备后续作答则 409。
- 替代题保持原任务类型、维度和来源。若原任务是补强题，撤销释放原配额槽位，替代题占用同一槽位，不额外消耗上限；Read 补强题仍保留清旗语义。
- 没有不同的新题时原作答保持不变。撤销不改 question.status；坏题操作仍单独标 bad_question。

## 测试

API 集成测试固定请求/响应与不能泄漏答案；服务单测覆盖 fail、Learn、新题替换、统计/补强/幂等/竞态；前端组件与 E2E 覆盖布局、反馈、进度、今日学习、撤销。
